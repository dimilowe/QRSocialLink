Architecture at a glance
Stack: Node.js + Express (API), SQLite via Prisma (fast + free on Replit), React + Vite (frontend), FFmpeg (media worker), BullMQ/Redis (or in-process queue fallback) for jobs.
Key objects: User, Campaign, Destination (A/B variants), QRCode, Frame (gif/mp4), RenderJob, ScanEvent.
Flow: Visitor scans QR → hits redirector (records event) → A/B chooser picks destination → redirect → analytics dashboard updates. Overlay Mode uses a render job to composite QR + frame into an MP4/GIF in multiple aspect ratios (9:16, 1:1, 16:9).

1.2 Prisma schema (SQLite for MVP)
model User {
  id           String  @id @default(cuid())
  email        String  @unique
  apiKey       String  @unique
  createdAt    DateTime @default(now())
  campaigns    Campaign[]
  frames       Frame[]
}

model Campaign {
  id            String   @id @default(cuid())
  userId        String
  name          String
  slug          String   @unique // used in redirect URL
  qrCodes       QRCode[]
  destinations  Destination[]
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt
  abStrategy    String   @default("epsilon-greedy") // or "weighted"
}

model Destination {
  id          String  @id @default(cuid())
  campaignId  String
  url         String
  weight      Int     @default(1) // for "weighted" strategy
  // live stats for bandit:
  impressions Int     @default(0)
  conversions Int     @default(0)
}

model QRCode {
  id           String  @id @default(cuid())
  campaignId   String
  label        String
  dynamicUrl   String  @unique // e.g. https://qr.yourdomain/r/abc123
  staticSvg    String? // stored SVG for print
  staticPng    String? // path to png
  overlayRenditions OverlayRendition[]
}

model Frame {
  id        String  @id @default(cuid())
  userId    String
  name      String
  type      String // "gif" | "mp4" | "png" (static)
  srcPath   String // uploaded asset path
  safeArea  String // JSON: {x,y,w,h} where QR should live
  loop      Boolean @default(true)
}

model OverlayRendition {
  id         String  @id @default(cuid())
  qrCodeId   String
  frameId    String
  status     String  @default("queued") // queued|processing|done|failed
  outputPath String?
  aspect     String // "9:16" | "1:1" | "16:9"
  createdAt  DateTime @default(now())
}

model ScanEvent {
  id          String  @id @default(cuid())
  campaignId  String
  qrCodeId    String
  variantId   String? // Destination id chosen
  userAgent   String?
  ipHash      String? // privacy-friendly hash
  ts          DateTime @default(now())
  referrer    String?
  country     String?
  platform    String? // ios/android/desktop
}
1.3 API routes
Auth (MVP): email + magic link or simple API key per user.
Campaigns
POST /api/campaigns – create {name, abStrategy}
GET /api/campaigns/:id – details + live stats
Destinations (A/B variants)
POST /api/campaigns/:id/destinations – add {url, weight}
PATCH /api/destinations/:id – update weight/URL
Bandit updates happen server-side after conversions (optional).
QR Codes
POST /api/campaigns/:id/qrs – create dynamic link, return SVG/PNG
GET /api/qrs/:id – fetch assets + overlay renditions
Frames & Upload
POST /api/frames – upload frame (gif/mp4/png) + safeArea
GET /api/frames – list
Overlay jobs
POST /api/overlays/render – {qrCodeId, frameId, aspects: ["9:16","1:1","16:9"]}
GET /api/overlays/:id – job status + output links
Redirector (critical path)
GET /r/:slug – resolves campaign by slug, choose variant via strategy, log ScanEvent, 302 redirect to destination.
Webhooks (optional)
POST /api/events/conversion – if you can signal “success” from the destination (button click/purchase), increment conversion on chosen Destination (supports bandit).
1.4 A/B strategy logic
Weighted random (simple):
Sum weights; pick a random int in [1..sum]; map to variant.
Epsilon-greedy bandit (better):
With probability ε (e.g., 0.1) explore: pick random variant.
Else exploit: pick variant with max conversions/impressions.
On conversion webhook, increment conversions.
1.5 Scan logging
Hash IP (salted SHA-256) and store UA, referrer, guessed country (basic GeoIP library if desired). Keep it privacy-respectful.

3) FFmpeg compositing (Overlay Mode)
3.1 Concepts
Frame: mp4/gif loop with a transparent or keyed area where the QR sits (the safe area).
QR layer: convert SVG → PNG (e.g., 1024×1024), then scale to safeArea.w × safeArea.h.
Compositions: export for 9:16, 1:1, 16:9. If the frame is a different aspect, letterbox with black (or transparent if webm).
3.2 Worker process
A simple job consumer that:
Loads Frame.srcPath and QRCode.staticPng
Scales frame to target aspect/size (e.g., 1080×1920)
Scales QR to safeArea
Overlays QR onto frame for the full duration (loop if GIF)
Outputs .mp4 and an auto-looping .gif teaser (optional)
3.3 Example commands
Scale base frame to 1080×1920 (pad if needed):
ffmpeg -y -i frame.mp4 -vf "scale=1080:-2, pad=1080:1920:(ow-iw)/2:(oh-ih)/2:color=black" -r 30 frame_9x16.mp4
Overlay QR (PNG) at safe area (x,y,w,h in pixels):
# Pre-scale QR to the safe area size
ffmpeg -y -i qr.png -vf "scale=400:400" qr_scaled.png

# Composite for full duration
ffmpeg -y -i frame_9x16.mp4 -i qr_scaled.png -filter_complex "overlay=100:120:format=auto" -c:a copy out_9x16.mp4
If the frame is a GIF: first convert to MP4 loop:
ffmpeg -y -stream_loop -1 -t 8 -i frame.gif -vf "fps=30,scale=1080:-2:flags=lanczos" frame_loop.mp4
ffmpeg -y -i frame_loop.mp4 -i qr_scaled.png -filter_complex "overlay=100:120" out_9x16.mp4
Optional glow/brand text layer:
Pre-render PNG of text/logo (brand.png), then:
ffmpeg -y -i out_9x16.mp4 -i brand.png -filter_complex "overlay=W-w-60:H-h-60" out_brand_9x16.mp4
Generate a short GIF teaser (for previews):
ffmpeg -y -i out_9x16.mp4 -t 3 -vf "fps=12,scale=540:-2:flags=lanczos" out_9x16.gif
Store outputs under /public/renders/{user}/{campaign}/{qrId}/{aspect}/…
3.4 Job API
POST /api/overlays/render enqueues a RenderJob for each aspect.
Worker writes outputPath + sets status to done (or failed with logs).
4) Overlay Mode: how it behaves on social
You cannot make the video itself “interactive” on TikTok/IG. The overlay is visual only.
Interaction happens when viewers scan the QR or follow on-screen CTA to your bio link.
Best practices:
Include animated border/pulse to draw eye to the QR.
Add subtitle CTA: “Scan me” or “Open Camera to scan”.
Export 9:16 for TikTok/Reels, 1:1 for feed, 16:9 for YouTube.
